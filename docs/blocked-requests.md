## Where aisle data stands

Checked 2026-11-12: the search page's product records (25 fields) have no aisle or
store-location field, and the page isn't tied to a store.

The **Morrisons More** app (`com.morrisons.matchandmore.app`, v11.1.0, Capacitor web
app) does have per-store aisles. Read from its unpacked web code (`assets/public/main.*.js`):
- Items carry `aisle`, `aisleDescription`, `aisleStoreId`; the list only shows an aisle
  when `aisleStoreId` matches the selected store, and sorts/groups items by aisle.
- The shopping list sends `storeId` + `storeName` + the typed product name and gets back
  `products` / `alternativeProducts`, each with a `location`.
- Needs a login (Firebase / Auth0 sign-in code is bundled).
- Backend = Firebase callable functions in `europe-west2` (project id is in the APK's
  `res/values/strings.xml`; not copied here). Product finder calls `findProduct` with
  `{searchId, sessionId, storeId, storeName, userInput}`; also `scanProductByBarcode`,
  `getProductPrice`, `createUserSession`. Response: `{products, alternativeProducts,
  matchMessage}`, each product `{title, product_id, ranking, location, locationDescription, img}`.
- 2026-11-12 probe: one anonymous `POST .../findProduct` with an empty payload ->
  **401 UNAUTHENTICATED** ("This request is unauthenticated"). Needs a signed-in user.
  Not retried. Whether App Check is also enforced: unknown.
- The app downloads newer web code in the background (LiveUpdates), so the bundle on
  disk may lag the live app.
